# coverage_areas.txt - the auditable area classification for the portable-C
# coverage metric (AGENTS.md "Completion metric").
#
# WHY THIS FILE IS DATA AND NOT CODE: the metric has two halves and they must
# not be confused. tools/coverage.ps1 MEASURES (line counts, recomputed from
# the pinned reference every run). THIS FILE JUDGES (what fraction of each
# area the port actually covers). The judgement is not derivable from a line
# count, so it lives here in a form a reviewer can read, argue with, and edit.
#
# FORMAT (pipe-separated, '#' starts a comment):
#   <id>|<name>|<covered_fraction>|<rationale>|<glob;glob;...>
#
#   id                 stable area key, referenced from AGENTS.md + todo.md
#   name               human label
#   covered_fraction   0.0 .. 1.0 - the ported share of that area
#   rationale          WHY that fraction, in one line. This is the audit
#                      surface: a fraction with no reason is not reviewable.
#   glob               ';' -separated paths relative to
#                      third_party/SVT-AV1/Source/Lib. A file may appear in at
#                      most ONE area; coverage.ps1 reports any file matched by
#                      two areas, and any Codec file matched by none (as the
#                      drift detector - a file added to the pinned reference
#                      shows up as UNASSIGNED rather than silently ignored).
#
# A file in Codec/ or C_DEFAULT/ matched by no glob is counted in the
# 'unassigned' row, so the area rows ALWAYS reconcile to the directory total
# without anyone asserting the reconciliation by hand.
#
# The fraction is a judgement about FUNCTIONAL coverage, not about our line
# count. A ported primitive that is 300 of our lines but 30,000 of SVT's moves
# the number by 30,000. That is deliberate: the metric asks "how much of SVT
# is here", not "how many lines did we type".
#
# MEASURED 2026-09-27. Re-run tools/coverage.ps1 after ANY edit here; the
# number quoted in AGENTS.md must come from that run, never from this file.
